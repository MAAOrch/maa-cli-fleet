## 1. 排班要解决的问题（实测）

排班前日常是**纯理智自循环**：跑完按「理智差 × 6 分钟」排下一次。相位由上一次跑的时刻决定，
会永远带着历史漂移 —— 10-02 全量迁移后，53 个日常的理智满点几乎全挤在 10-03 早半天：
00:00–10:59 落 50 台（05:00–09:00 一小时段 36 台，最长 12 台同时重叠 @06:00），
10:40 之后只剩 3 台，其余时段空转。4 槽 24h 能干 96 槽·小时，实际需求约 22 槽·小时（23%）
—— 不是跑不完，是**什么时候跑**没管。

排班过程中挖出两个真 bug（都已修，见 §5）：

1. **时区 bug（老代码，危害大）**：state 里的时间戳是本地墙钟字符串（`time.Now().Format`），
   但派车判据用 `time.Parse`（无时区 → 按 **UTC**）比较 → 所有定时整体**晚 8 小时**执行
   （CST）。表现就是"排到的点到了却不发车、过 8 小时才动"，10-02 夜里 l2/l4/l7 的
   `planAt=22:45` 到点不发车就是这个原因。修法：统一 `parseStamp()`（`ParseInLocation(time.Local)`）。
2. **网格原点漂移（我写 roster 时引入、当天修掉）**：16h 不整除 24h，若用"当天的锚点"当网格
   原点，相位会随参考日期翻 8h（10-02 一套点、10-03 另一套点）。修法：原点固定到 2000-01-01
   的同一钟点，网格是绝对时间上的等差序列（回归测试 `TestGridStableAcrossMidnight`）。

## 2. 口径（roster.json，连续模式）

```json
{ "enabled": true, "cycleHours": 16, "minGapHours": 12, "reseed": true,
  "base": "00:15",
  "order": ["a01","a02","a03", "...", "l7"] }
```

- **一条连续轮盘**：52 台按顺序铺在 16h 轮盘上，**每 18.5 分钟一位**（960/52）；
  每台的班次 = `锚点 + 16h × k`，16h 回 160 点理智、不满上限（196–210）→ 不浪费；
- **间隔**：两次之间至少 `minGapHours`（12h）防一天两跑；12h 是留了同班排队的余量
  （minGap 逼近 16h 会跳过整班 → 该号变 32h 一轮）；
- **发车口径**：`runner.json` 里 `"planEarlyMin": 0` —— 前瞻排班不再提前 2h 拉车，
  **就在班次点上发车**（原来默认提前 120 分钟）；
- **reseed=true**：启动时把每台的 NextDue 对齐到"从现在起的第一个网格点"（= 清掉旧排班）。
  这条只在"要重铺班表"时用；日常跑完后由 `scheduleNextDaily` 自然落在网格上，不需要 reseed；
  要彻底关掉它：把 `reseed` 去掉或置 false（**改数据，不用换 exe**）；
- **没排班的号**（新账号、不在 order 里）= 旧行为（理智自循环），逐台过渡；
  `roster.json` 不存在 / `enabled=false` → 整块退回旧行为（回滚开关）。

## 4. 怎么用（机端）

```powershell
# 连续班（默认）：全部启用日常号，按顺序均匀铺开
python <项目>\tools\gen_roster.py                     # 起点=下一个整 5 分钟
python <项目>\tools\gen_roster.py --base 00:15 --reseed
python <项目>\tools\gen_roster.py --dry               # 只看排位，不写文件
# 三班倒（备选口径）
python <项目>\tools\gen_roster.py --mode shifts --anchors 04:00,12:00,20:00

fleet.exe runner -status     # [班表] 段：加载行 + 接下来 16 位
```

改 `roster.json` 后用 `taskkill /IM fleet.exe /F` 重启一次（看门狗 10 分钟内拉起）即可生效。
